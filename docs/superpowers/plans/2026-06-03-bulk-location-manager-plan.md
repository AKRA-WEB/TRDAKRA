# 📋 แผนการพัฒนาระบบจัดโลเคชั่นสินค้าแบบกลุ่ม (Bulk Location Manager)

**วันที่จัดทำ:** 3 มิถุนายน 2026  
**แอปพลิเคชัน:** TRDAKRA (ระบบเบิกย้ายสาขา TRD)  
**เป้าหมายหลัก:** ให้ผู้ใช้สามารถเลือกสินค้าหลายรายการพร้อมกัน แล้วระบุ "ชั้น + โซน" (โลเคชั่นเดียว) ได้ในครั้งเดียว โดยออกแบบมาให้ใช้งานได้ลื่นไหล รวดเร็วบนมือถือ และประหยัดทราฟฟิกเครือข่าย (โหลดและบันทึกข้อมูลได้รวดเร็ว)

## 1. 📱 UX/UI Flow บนมือถือ (ลื่นไหลภายใน 3 ขั้นตอน + แท็บแยกของสินค้าที่ยังไม่มีโลเคชั่น)

แนวคิดใหม่ที่เราจะใช้คือ **"เลือกของที่กองอยู่ตรงหน้าก่อน (Product-First Selection) แล้วย้ายเข้าโลเคชั่นพร้อมกัน"** พร้อมกับมี **แท็บแยกแสดงเฉพาะ "สินค้าที่ยังไม่มีโลเคชั่น"** อย่างชัดเจน เพื่อให้พนักงานรู้ทันทีว่าเหลือสินค้าตัวไหนบ้างที่ต้องนำไปจัดตำแหน่ง

### ขั้นตอนการทำงาน (User Flow):
1. **เข้าสู่หน้าจัดโลเคชั่น:** ระบบจะแลนด์ดิ้ง (Default Land) อยู่บนแท็บ **"ยังไม่มีโลเคชั่น"** ทันที เพื่อให้พนักงานเห็นรายการที่ยังค้างอยู่
2. **เปิดโหมดเลือกกลุ่ม (Bulk Mode):** กดปุ่มไอคอน `checkbox` หรือ `เลือกหลายรายการ` ที่มุมขวาบน
3. **เลือกสินค้าแบบกลุ่ม:** 
   - สามารถกด **"เลือกทั้งหมด (Select All)"** ในแท็บสินค้าที่ยังไม่มีโลเคชั่น เพื่อจัดการสินค้าทั้งหมดในแท็บนั้นพร้อมกัน
   - หรือพิมพ์ค้นหา/เลือกเป็นรายตัว
4. **จัดโลเคชั่นกลุ่ม (Bulk Assign):** กดแถบล่างลอยตัว **"📍 จัดโลเคชั่นกลุ่ม (X รายการ)"** -> เลือก ชั้น/โซน -> กดบันทึก -> บันทึกแบบ Batch สิ้นสุดใน 2 วินาที

## 3. ⚡ เทคนิคการเพิ่มความเร็วและการตอบสนอง (Performance & Mobile Speed)

เพื่อให้แอปทำงานได้รวดเร็วตามที่ผู้ใช้เน้นย้ำ โดยเฉพาะในสภาวะอินเทอร์เน็ตมือถือที่ไม่เสถียร และมีจำนวนสินค้าที่ยังไม่มีโลเคชั่นจำนวนมาก (หลายร้อยตัว) เราจะใช้เทคนิคสำคัญดังนี้:

### 3.1 การส่งข้อมูลแบบ Batch API (ลดรอบ HTTP Request)
*   **ปัญหาแบบเดิม:** หากเลือกสินค้า 10 ตัวแล้วสั่งย้าย ระบบต้องยิง POST API ไปยัง Apps Script 10 รอบ (ใช้เวลา 15-20 วินาที และมีโอกาสล้มเหลวสูง)
*   **แนวทางใหม่:** เราจะเพิ่ม API `updateProductDetailsBatch` ในไฟล์ `Code.gs` เพื่อรับค่าในรูปแบบ JSON:
    ```json
    {
      "action": "updateProductDetailsBatch",
      "names": ["แป้งเค้กพัดโบก 1kg", "นมข้นหวานมะลิ 2kg"],
      "floor": "2",
      "location": "2B-04",
      "parLevel": 0
    }
    ```
    เซิร์ฟเวอร์จะประมวลผลและเขียนข้อมูลลงชีต **ภายในคำขอ (Request) เดียว** ช่วยลดระยะเวลาเชื่อมต่อเหลือเพียง **1.5 - 2 วินาที**

### 3.2 การอัปเดต DOM แบบเจาะจง (Instant Screen Feedback)
*   เมื่อผู้ใช้แตะเลือกสินค้าในหน้าเว็บ เราจะเปลี่ยน CSS class ของแถวและสลับสถานะ Checkbox ใน DOM ทันทีผ่าน JavaScript โดย **ไม่เรียกใช้งานฟังก์ชัน `render()` ทั้งหน้า** วิธีนี้ช่วยให้หน้าจอมีการตอบสนองทันที (Instant 60fps) ปราศจากอาการจอกระตุกหรือหน่วงเมื่อมีรายการสินค้าจำนวนมาก
*   หลังจากบันทึกข้อมูลสำเร็จ จะใช้วิธีเปลี่ยนค่าใน `state.products` ภายในเครื่อง และลบข้อมูล Cache ออกเพื่อให้ข้อมูลถูกต้องเสมอในการใช้งานครั้งถัดไป

### 3.3 ระบบจำกัดจำนวนแสดงผล และ ปุ่มโหลดเพิ่ม (Lazy Rendering & Load More)
*   **ป้องกันการกระตุกของมือถือ:** หน้าจอจะไม่วาด (Render) แถวของสินค้าพร้อมกันหลายร้อยตัว เพราะจะทำให้เบราว์เซอร์บนมือถือค้าง แต่จะจำกัดจำนวนแสดงผลครั้งแรกไว้ที่ **40 รายการแรก**
*   **ปุ่ม "แสดงเพิ่มอีก 40 รายการ":** หากมีสินค้าเกิน 40 รายการ ด้านล่างสุดของรายการจะมีปุ่มแสดงเพิ่มอย่างสวยงาม เพื่อให้ผู้ใช้กดโหลดรายการต่อไปขึ้นมาแสดงแบบรวดเร็วโดยไม่โหลดหน้าใหม่
*   **ปุ่มเลือกทั้งหมดเฉพาะที่แสดงผล:** เมื่อกด "เลือกทั้งหมด" ระบบจะทำการเลือกเฉพาะสินค้าที่แสดงผลอยู่บนจอขณะนั้น ทำให้ผู้ใช้งานควบคุมการจัดการข้อมูลได้แม่นยำ

### 3.4 การสะสมการเลือกข้ามการกรอง/ค้นหา (Selection Accumulation)
*   **ปัญหาทั่วไป:** พนักงานแตะเลือกแป้งไป 3 ตัว พอพิมพ์ในช่องค้นหาใหม่เพื่อหาเนย ปรากฏว่าเนยขึ้นมาแต่สิ่งที่เลือกไว้ก่อนหน้าหายไป!
*   **แนวทางใหม่:** สเตตการจดจำการเลือก (`state.locationSelectedItems`) จะถูกเก็บแยกเป็นอิสระ พนักงานสามารถค้นหาคำว่า "แป้ง" -> เลือก 3 รายการ -> ลบพิมพ์ค้นหาใหม่เป็น "เนย" -> เลือกเพิ่มอีก 2 รายการ -> ยอดเลือกสะสมจะเพิ่มขึ้นเป็น **5 รายการ** โดยของเก่าไม่หายไป ทำให้การจัดกลุ่มพิกัดข้ามชื่อสินค้าเป็นเรื่องง่ายและสะดวกสูงสุด

### 3.5 ระบบล้าง Cache แบบชาญฉลาด (Smart Caching)
*   แอปนี้มีระบบ Cache ข้อมูลสินค้า (`TRDAKRA_DATA`) อยู่แล้ว เมื่อบันทึกสำเร็จระบบจะรีเซ็ต Cache ในเครื่อง และทำการดึงข้อมูลใหม่เบื้องหลังเพื่ออัปเดตให้ข้อมูลสอดคล้องกัน โดยไม่ต้องโหลดหน้าเว็บใหม่ทั้งหมด

### ส่วนที่ 1: อัปเดตไฟล์ Google Apps Script ([Code.gs.txt](file:///c:/Dev/WEBAPP/TRDAKRA/Code.gs.txt))
เพิ่มฟังก์ชันสำหรับบันทึกข้อมูลสินค้าทีละหลายรายการเพื่อเพิ่มความเร็วในการบันทึก:
```javascript
// เพิ่มในฟังก์ชัน doPost(e)
if (body.action === 'updateProductDetailsBatch') {
  var ok = updateProductDetailsBatch(body.names, body.floor, body.location, body.parLevel);
  return ContentService.createTextOutput(JSON.stringify({ status: ok ? 'success' : 'error' })).setMimeType(ContentService.MimeType.JSON);
}

// สร้างฟังก์ชันใหม่สำหรับ Batch Update
function updateProductDetailsBatch(itemNames, floor, location, parLevel) {
  try {
    var ss = SpreadsheetApp.openById(SHEET_ID);
    var sheet = ss.getSheetByName(PRODUCT_SHEET_NAME);
    if (!sheet) return false;
    
    var lastRow = sheet.getLastRow();
    var lastCol = sheet.getLastColumn();
    if (lastRow < 2) return false;
    
    var headers = sheet.getRange(1, 1, 1, lastCol).getValues()[0];
    var nameColIndex = headers.indexOf("Product name");
    if (nameColIndex === -1) nameColIndex = 1;
    
    var floorColIndex    = headers.indexOf("Floor");
    var locationColIndex = headers.indexOf("Location");
    var parLevelColIndex = headers.indexOf("Par Level");
    
    // ดึงค่าทั้งหมดมาจัดการในหน่วยความจำ (รวดเร็วกว่าเขียนทีละแถว 100 เท่า)
    var nameValues = sheet.getRange(2, nameColIndex + 1, lastRow - 1, 1).getValues();
    var floorValues = floorColIndex >= 0 ? sheet.getRange(2, floorColIndex + 1, lastRow - 1, 1).getValues() : [];
    var locValues = locationColIndex >= 0 ? sheet.getRange(2, locationColIndex + 1, lastRow - 1, 1).getValues() : [];
    var parValues = parLevelColIndex >= 0 ? sheet.getRange(2, parLevelColIndex + 1, lastRow - 1, 1).getValues() : [];
    
    var namesToUpdate = {};
    itemNames.forEach(function(name) { namesToUpdate[name.trim()] = true; });
    
    var updated = false;
    for (var i = 0; i < nameValues.length; i++) {
      var name = nameValues[i][0] ? nameValues[i][0].toString().trim() : '';
      if (namesToUpdate[name]) {
        if (floor !== undefined && floor !== null) floorValues[i][0] = floor;
        if (location !== undefined && location !== null) locValues[i][0] = location;
        if (parLevel !== undefined && parLevel !== null && parLevel > 0) parValues[i][0] = parseInt(parLevel);
        updated = true;
      }
    }
    
    // บันทึกกลับคืนแผ่นงานทีเดียวแบบรวดเร็ว
    if (updated) {
      if (floorColIndex >= 0) sheet.getRange(2, floorColIndex + 1, lastRow - 1, 1).setValues(floorValues);
      if (locationColIndex >= 0) sheet.getRange(2, locationColIndex + 1, lastRow - 1, 1).setValues(locValues);
      if (parLevelColIndex >= 0) sheet.getRange(2, parLevelColIndex + 1, lastRow - 1, 1).setValues(parValues);
      return true;
    }
    return false;
  } catch (error) {
    Logger.log("Error in updateProductDetailsBatch: " + error.toString());
    return false;
  }
}
```

### ส่วนที่ 2: อัปเดตไฟล์หน้าบ้าน ([index.html](file:///c:/Dev/WEBAPP/TRDAKRA/index.html))
1. **โครงสร้าง State ใหม่:**

4. **ฟังก์ชันบันทึกข้อมูล:**
   * ปรับปรุง `confirmLocationSheet()` ให้ตรวจสอบสถานะ หากอยู่ในโหมดกลุ่มให้เรียกใช้ POST API ตัวใหม่ `updateProductDetailsBatch` จากนั้นอัปเดต `state.products` ทุกตัวในหน่วยความจำและปิดหน้าต่างทำงานทันที
